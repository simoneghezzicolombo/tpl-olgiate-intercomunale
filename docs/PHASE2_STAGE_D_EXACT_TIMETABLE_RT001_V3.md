# Phase 2 Stage D — Exact timetable RT-001 V3

## Scope and lineage

This workstream applies the independently audited exhaustive Stage-D kernel to
the repaired RT-001 budget-lossless manifest.  Its upstream contract is
`PHASE2_LOSSLESS_DAILY_TIMING_INPUT_MANIFEST_RT001_V3`; all cardinalities are
read from that validation artifact and are not prerequisites embedded in code.

The stage does not select a decision budget, calendar, recovery value,
topology, PRIMARY, or RUNNER-UP.

## Exact phase and budget rule

For every `scenario_id + headway + span` timing problem, every public route is
assigned an integer phase in `0..headway-1`.  The full Cartesian product is
enumerated.  There is no sampling, heuristic pruning, cross-scenario
equivalence, or weighted passenger score.

For every budget-qualified Passenger Utility plan context, Stage D:

1. computes exact daily bus-km from the departures generated by each phase
   vector and the closed vehicle-cycle route distance;
2. multiplies exact daily production by that context's retained annual service
   days;
3. discards only phase vectors whose exact annual production exceeds that
   context's hard cap;
4. optimises the certified S8 transfer-quality hierarchy among the remaining
   exact-feasible vectors.

Thus an upstream `SOME_PHASES_BUDGET_FEASIBLE` context is retained whenever at
least one exact vector is within cap, including contexts recovered by RT-001
where the continuous audit approximation would have failed.

## Passenger and S8 semantics

The S8 target is the exact maximum of the certified continuous transfer-quality
function over the finite official target-event set.  Target localisation to the
two events bracketing the ideal time is mathematically exact for that function.

Passenger BUS_TO_RAIL returns are scored only when the public route itself
returns to the hub and the return event is inside the declared
start-inclusive/end-exclusive service span.  A technical vehicle-only closure
never becomes a passenger return.

## Vehicle blocks

The selected exact phase vector is evaluated independently for recovery 5, 10,
and 15 minutes.  Exact minimum fleet counts and deterministic trip-to-vehicle
block assignments are materialised for all three sensitivities.  None is
selected.

## Evidence boundary

The selected phase is an exact timetable choice within each retained Stage-C
context, not a final network recommendation.  Reliability and missed-connection
robustness remain Stage E evidence.  The current-service comparison remains a
certified localisable lower bound, and final selection remains blocked until the
explicit Decision Contract supplies `decision_budget_km` and
`uncertainty_band_min`.
